## 1. Краткое описание

**Голограмма (ДОЭ)** здесь — это матрица $128\times128$ значений фазы от $-\pi$ до $\pi$.
Её выводят на пространственно-временной модулятор света (ПВМС), через который проходит лазерный луч.
Свет дифрагирует и на заданных расстояниях от ПВМС собирается в изображения.

Нужно разработать **нейросеть**, которая по 4 объектным изображениям за один прямой проход
выдаёт один фазовый ДОЭ, восстанавливающий каждое изображение на своём расстоянии.
Классические методы (Герчберга–Сэкстона, Фиенап) требуют сотен итераций, нейросеть должна быть быстрее.

**Суть подхода:** обучение **без учителя** с физическим слоем. Эталонных ДОЭ нет, поэтому
выход сети пропускается через дифференцируемый расчёт дифракции Френеля, а функция потерь
сравнивает восстановленные изображения с исходными.

```
4 изображения ──► нейросеть ──► фаза φ ──► [слой Френеля на 4 расстояниях] ──► 4 восстановленных ──► потери
 (4×128×128)      (U-Net)     (128×128)         (фиксированный, без весов)        (4×128×128)     vs. исходные
```

### 2.2 Уточнения организаторов

- На вход подаются только полутоновые одноканальные PNG с разрядностью 8 бит.
- Сравниваются амплитуды $|K|$, не интенсивности $|K|^2$. Перед сравнением **каждое** исходное и восстановленное изображение независимо нормируется на собственный максимум до 1.
- КК и ИСС оцениваются и публикуются независимо; единого итогового балла нет. Формального приоритета нет, но ИСС немного важнее при выборе инженерных решений.

### 2.3 Границы допустимого метода

- Итоговый ДОЭ для новой четвёрки должен выдавать нейросетевой метод; после предсказания сети запрещена итеративная подстройка фазы под эту конкретную четвёрку.
- Дифференцируемая физическая модель Френеля внутри сети разрешена. Adam во время офлайн-обучения обновляет **веса сети**, а не фазу конкретного финального ДОЭ.
- Классические методы допустимы только для подготовки вспомогательных обучающих данных или абляций; они не входят в финальный конвейер синтеза и не могут уточнять его результат.
- Для проверки используется центрированная сетка и прямой БПФ: `fftshift(fft2(ifftshift(...)))`.

## 3. Постановка задачи для машинного обучения

**Тип задачи:** обучение без учителя с дифференцируемым физическим слоем (physics-informed / unsupervised).

**Вход:** четвёрка изображений, нормированная по максимуму каждого канала

$$X=(I_1^{(n)},I_2^{(n)},I_3^{(n)},I_4^{(n)})\in[0,1]^{4\times128\times128}.$$

**Модель:** сеть $f_\theta$, выход которой ограничен диапазоном фазы:

$$\varphi=\pi\cdot\tanh\big(f_\theta(X)\big)\in[-\pi,\pi]^{128\times128}.$$

**Физический слой** (фиксированный, дифференцируемый): $\hat I_m=\mathcal{P}_{z_m}(\varphi)$, $m=1..4$.

**Функция потерь:**

$$\mathcal{L}(\theta)=\frac{1}{4}\sum_{m=1}^{4}\Big[\big(1-\mathrm{КК}(I_m,\hat I_m)\big)+1{,}1\,\big(1-\mathrm{ИСС}(I_m,\hat I_m)\big)\Big].$$

**Оптимизация:**

$$\theta^{*}=\arg\min_{\theta}\ \mathbb{E}_{X\sim\mathcal{D}}\ \mathcal{L}(\theta).$$

**Выходы метода:** ДОЭ $\varphi$ и четыре восстановленных изображения; качество оценивается по КК и ИСС.

**Важные свойства задачи:**

1. **Задача переопределена.** Неизвестных 16 384 (фаза $128\times128$), условий $4\times16\,384$ (яркости 4 изображений).
   Точного решения в общем случае нет, сеть ищет компромисс между плоскостями. Значения КК и ИСС, равные 1, недостижимы.
2. **Нет «правильных» ответов.** Эталонных ДОЭ нет, поэтому обучение идёт только через физический слой.
3. **Обобщение.** Если обучать только на 4 конкретных изображениях, сеть запомнит ответ (это будет оптимизация, а не метод).
   Основной результат — модель, обученная на разнообразном наборе четвёрок. Дообучение на конкретных 4 картинках — опциональное дополнение, его нужно чётко маркировать.

## 4. Физическая модель

### 4.1 Формула

Поле в плоскости восстановления на расстоянии $z$:

$$K(x,y)=\frac{e^{jkz}}{j\lambda z}\;e^{\frac{j\pi}{\lambda z}(x^2+y^2)}\cdot\mathrm{FFT}\!\left\{H(u,v)\,e^{\frac{j\pi}{\lambda z}(u^2+v^2)}\right\},\qquad H(u,v)=e^{j\varphi(u,v)}.$$

Здесь $k=\frac{2\pi}{\lambda}$, $(u,v)$ — координаты в плоскости ПВМС, $(x,y)$ — в плоскости восстановления.

Для изображения нужен только **модуль** поля, поэтому множители с чисто фазовым вкладом
($e^{jkz}$, $j$, $e^{\frac{j\pi}{\lambda z}(x^2+y^2)}$) можно опустить:

$$|K(x,y)|=\frac{1}{\lambda z}\,\Big|\mathrm{FFT}\big\{e^{j\varphi(u,v)}\,e^{\frac{j\pi}{\lambda z}(u^2+v^2)}\big\}\Big|.$$

### 4.2 Дискретизация

Сетка плоскости ПВМС: $u_n=(n-N/2)\,\Delta u$, $N=128$, $\Delta u=10$ мкм.
Шаг в плоскости восстановления (свойство одного FFT):

$$\Delta x_m=\frac{\lambda z_m}{N\,\Delta u}.$$

| $z$, мм | $\Delta x$, мкм | Поле зрения $N\Delta x$, мм |
|---|---|---|
| 24,1 | 10,02 | 1,28 |
| 25,3 | 10,52 | 1,35 |
| 26,5 | 11,02 | 1,41 |
| 27,7 | 11,51 | 1,47 |

Масштаб в плоскостях разный, но сравнение идёт попиксельно по массивам $128\times128$, поэтому это не мешает; это лишь одна из причин конфликта между плоскостями.

### 4.3 Проверка условия дискретизации (алиасинг)

Квадратичная фаза $e^{\frac{j\pi}{\lambda z}u^2}$ имеет локальную частоту $\frac{u}{\lambda z}$. На краю апертуры $u_{max}=0{,}64$ мм;
частота Найквиста $\frac{1}{2\Delta u}=5\cdot10^{4}$ 1/м.

| $z$, мм | $\frac{u_{max}}{\lambda z}$, 1/м | Доля от Найквиста |
|---|---|---|
| 24,1 | 49 920 | 99,8 % |
| 25,3 | 47 550 | 95,1 % |
| 26,5 | 45 400 | 90,8 % |
| 27,7 | 43 430 | 86,9 % |

Все значения ниже Найквиста, но при $z=24{,}1$ мм запас почти нулевой. Это значит, что условия задачи подобраны «на грани»,
поэтому квадратичную фазу нужно считать в **float64** (потом приводить к complex64), иначе накопится ошибка.

### 4.4 Эталонная реализация физического слоя (PyTorch)

```python
import math
import torch

def _quad_kernel(N, dx, wavelength, z, device):
    c = (torch.arange(N, device=device, dtype=torch.float64) - N / 2) * dx
    U, V = torch.meshgrid(c, c, indexing="ij")
    return torch.exp(1j * math.pi / (wavelength * z) * (U**2 + V**2)).to(torch.complex64)

def fresnel_amplitude(phase, z, wavelength=532e-9, dx=10e-6):
    """phase: (B,1,N,N), радианы  ->  |K|: (B,1,N,N) в плоскости z."""
    N = phase.shape[-1]
    quad = _quad_kernel(N, dx, wavelength, z, phase.device)
    field = torch.exp(1j * phase) * quad
    K = torch.fft.fftshift(
        torch.fft.fft2(torch.fft.ifftshift(field, dim=(-2, -1))), dim=(-2, -1)
    )
    return K.abs() / (wavelength * z)

def reconstruct(phase, zs=(24.1e-3, 25.3e-3, 26.5e-3, 27.7e-3), **kw):
    """-> (B,4,N,N): амплитуды во всех плоскостях."""
    return torch.cat([fresnel_amplitude(phase, z, **kw) for z in zs], dim=1)
```

Ядро `_quad_kernel` лучше кэшировать (оно зависит только от $z$ и $N$).
Физический слой считать в fp32/fp64, **не** в fp16 (mixed precision включать только для сети).
Конвенция подтверждена организаторами: применяется прямой `fft2` с `ifftshift` перед ним и `fftshift` после него.

### 4.5 Нормировка восстановленного изображения

По ТЗ и уточнению организаторов сохраняются **модули значений** поля, то есть восстановленное изображение это амплитуда $|K|$ (а не интенсивность $|K|^2$).

Перед сравнением нормируется **каждое изображение пары**, одинаково в обучении и в финальной оценке:

$$I_m^{(n)}=\frac{I_m}{\max I_m+\varepsilon},\qquad
\hat I_m=\frac{|K_m|}{\max|K_m|+\varepsilon}\in[0,1],\qquad
\text{png}=\mathrm{round}\big(255\,\hat I_m\big).$$

Финальные метрики считаются по сохранённым 8-битным png восстановленных изображений и 8-битным исходным изображениям.

### 4.6 Квантование ДОЭ

ДОЭ сохраняется в 8 бит:

$$p=\mathrm{round}\!\left(255\cdot\frac{\varphi+\pi}{2\pi}\right),\qquad \varphi_q=\frac{2\pi\,p}{255}-\pi.$$

**Финальные восстановленные изображения считаются от $\varphi_q$ (после чтения png), а не от «чистого» $\varphi$.**
Ошибка квантования небольшая (шаг $\frac{2\pi}{255}\approx0{,}025$ рад), но её нужно учесть при проверке.

## 5. Метрики качества

Для каждой из 4 пар (исходное $A$, восстановленное $B$):

**Коэффициент корреляции Пирсона** (инвариантен к масштабу яркости):

$$\mathrm{КК}=\frac{\sum_{i,j}(A_{ij}-\bar A)(B_{ij}-\bar B)}{\sqrt{\sum_{i,j}(A_{ij}-\bar A)^2\ \sum_{i,j}(B_{ij}-\bar B)^2}}.$$

**Индекс структурного сходства:**

$$\mathrm{ИСС}=\frac{(2\bar A\bar B+c_1)(2\sigma_{AB}+c_2)}{(\bar A^2+\bar B^2+c_1)(\sigma_A^2+\sigma_B^2+c_2)}.$$

Для обоих идеал равен 1. В отчёте метрики не объединяются в единый итоговый балл: приводятся КК и ИСС для
каждой из четырёх пар и их отдельные средние. При равном прочем ИСС считается немного более важной метрикой.

Реализация:
- обучение: КК самописный (3 строки на torch), ИСС — `pytorch_msssim.ssim` (дифференцируемый), `data_range=1.0`;
- финальная оценка: сначала каждый исходный и восстановленный 8-битный png нормируется на собственный максимум,
  затем применяются `skimage.metrics.structural_similarity` и `numpy.corrcoef`/`scipy.stats.pearsonr`
  (так воспроизведёт любой эксперт). Расхождение обучающего и финального ИСС в третьем знаке — норма, но его надо проверить.

## 6. Данные

**Ключевой вопрос:** в итоге оцениваться будут «4 исходных объектных изображения». Если организаторы выдают их заранее — они и есть тестовая четвёрка.
Если нет, модель должна работать на **любых** четвёрках. В обоих случаях основной режим — обобщающая модель.

**Зафиксированный набор для baseline:** множество случайных четвёрок одноканальных изображений
$128\times128$ со значениями в $[0,1]$. Для каждого из четырёх каналов источник выбирается независимо:

| Доля изображений | Источник | Состав и назначение |
|---|---|---|
| 60 % | процедурная генерация | буквы, цифры, окружности, прямоугольники, линии, кольца, точки и их комбинации; случайные положение, размер, толщина, поворот и контраст |
| 40 % | [BSDS500](https://www2.eecs.berkeley.edu/Research/Projects/CS/vision/bsds/) | случайные кропы естественных изображений, перевод в grayscale, resize/crop до $128\times128$; добавляют текстуры и сложные распределения яркости |

### 6.1 Точный протокол baseline-датасета

| Разбиение | Число четвёрок | Источник натуральной части | Назначение |
|---|---:|---|---|
| `train` | 24 000 | 200 изображений BSDS500 train | обучение весов |
| `val` | 2 000 | 100 изображений BSDS500 val | ранняя остановка и выбор чекпоинта |
| `test_internal` | 2 000 | 200 изображений BSDS500 test | однократная внутренняя проверка после выбора модели |

Каждая четвёрка содержит четыре **разных** целевых изображения. Для каждого из четырёх каналов с вероятностью
0,6 выбирается процедурный генератор и с вероятностью 0,4 — BSDS500. Таким образом, 60/40 — доля отдельных
целевых изображений, а не обязательная пропорция внутри каждой конкретной четвёрки. Финальная четвёрка от
организаторов не входит ни в одно из этих разбиений и не используется для выбора гиперпараметров.

Натуральное изображение приводится к grayscale (`PIL.convert("L")`), масштабируется так, чтобы меньшая сторона
была не меньше 128, затем из него выбирается случайный кроп $128\times128$. Кропы с $\sigma<0{,}05$ отбрасываются,
чтобы в обучении не доминировали почти однородные цели. Процедурный генератор создаёт один или несколько
объектов на чёрном фоне: буквы/цифры, окружности, прямоугольники, линии, кольца и точки; рандомизируются
положение, размер, толщина, поворот и яркость. В каждом изображении есть хотя бы один объект.

Ни изображения, ни фазовые маски не обязаны сохраняться в 28 000 папках. Вместо этого создаются
`data/manifests/{train,val,test_internal}.jsonl`: одна строка на четвёрку, содержащая четыре seed либо
имя файла BSDS500 и координаты кропа. Генератор по манифесту воспроизводит в точности те же тензоры.

время обучения. MNIST/Fashion-MNIST допускаются только для smoke-теста конвейера, но не входят в итоговое
обучение.

В финальный архив сдачи входят использованные исходные изображения BSDS500, три манифеста и генератор

Правила:
- `Dataset.__getitem__` читает одну строку манифеста и формирует детерминированную четвёрку;

- тестовая четвёрка (когда будет известна) в обучение не попадает;
- все изображения приводятся к `float32`, форме `(4,128,128)` и затем независимо по каналам нормируются на собственный максимум в $[0,1]$.

Формат загрузки/сохранения png: одноканальный 8 бит (`PIL.Image.open(...).convert("L")`), никакого RGB.

## 7. Архитектура и функция потерь

### 7.1 Зафиксированная baseline-сеть

Baseline — обычный U-Net без предобученных весов, спектральных входов и обучаемых операций в физическом
слое. Входные яркости перед сетью переводятся из $[0,1]$ в $[-1,1]$; целевые изображения для loss остаются
в $[0,1]$.

Базовый блок:

```text
DoubleConv(cin, cout) =
    Conv2d(cin, cout, 3, padding=1, bias=False) → GroupNorm(8) → SiLU →
    Conv2d(cout, cout, 3, padding=1, bias=False) → GroupNorm(8) → SiLU
```

Точная архитектура:

| Этап | Операция | Выход |
|---|---|---|
| Вход | 4 целевых изображения | `(B, 4, 128, 128)` |
| `enc0` | `DoubleConv(4, 32)` | `(B, 32, 128, 128)` |
| `enc1` | `MaxPool2d(2)` + `DoubleConv(32, 64)` | `(B, 64, 64, 64)` |
| `enc2` | `MaxPool2d(2)` + `DoubleConv(64, 128)` | `(B, 128, 32, 32)` |
| `enc3` | `MaxPool2d(2)` + `DoubleConv(128, 256)` | `(B, 256, 16, 16)` |
| `bottleneck` | `MaxPool2d(2)` + `DoubleConv(256, 512)` | `(B, 512, 8, 8)` |
| `dec3` | bilinear upsample, `1×1: 512→256`, concat `enc3`, `DoubleConv(512, 256)` | `(B, 256, 16, 16)` |
| `dec2` | bilinear upsample, `1×1: 256→128`, concat `enc2`, `DoubleConv(256, 128)` | `(B, 128, 32, 32)` |
| `dec1` | bilinear upsample, `1×1: 128→64`, concat `enc1`, `DoubleConv(128, 64)` | `(B, 64, 64, 64)` |
| `dec0` | bilinear upsample, `1×1: 64→32`, concat `enc0`, `DoubleConv(64, 32)` | `(B, 32, 128, 128)` |
| Голова | `Conv2d(32, 1, 1)` и $\pi\tanh(\cdot)$ | `(B, 1, 128, 128)` |

Для bilinear upsample используется `align_corners=False`. В сети около 7,24 млн параметров. GroupNorm выбран
вместо BatchNorm, потому что размер батча ограничен четырьмя FFT на каждый пример; bilinear upsample вместо
транспонированной свёртки уменьшает риск шахматных артефактов. Bottleneck $8\times8$ даёт сети глобальный
контекст, а skip-соединения сохраняют пространственные детали.

### 7.2 Полный прямой проход

Сеть предсказывает только фазу. Формула Френеля не имеет обучаемых параметров:

$$
X^{(n)}\xrightarrow{f_\theta}\varphi=\pi\tanh(f_\theta(2X^{(n)}-1))
\xrightarrow{\mathcal P_{z_1},\ldots,\mathcal P_{z_4}}
A_m=|K_m|\xrightarrow{A_m/(\max A_m+\varepsilon)}\hat I_m.
$$

В baseline используется амплитуда $|K|$, а не интенсивность $|K|^2$. Нормировка выполняется независимо
для каждого примера и каждой плоскости. В физическом слое нет `detach`: градиент проходит от всех четырёх
реконструкций к фазе и далее к весам U-Net.

### 7.3 Функция потерь

Baseline оптимизирует только две метрики из ТЗ с небольшим перевесом ИСС:

$$
\mathcal{L}_{base}=\frac{1}{4}\sum_{m=1}^{4}
\left[(1-\mathrm{КК}_m)+1{,}1\,(1-\mathrm{ИСС}_m)\right].
$$

Коэффициент $1{,}1$ — небольшая инженерная поправка в пользу ИСС согласно уточнению организаторов; он не
создаёт «итоговую метрику» и не меняет раздельную отчётность. MSE, адаптивные веса плоскостей, штраф за фон
и другие регуляризаторы в baseline не входят. Их можно добавлять только как отдельные эксперименты с
аблацией. Финально КК и ИСС всё равно публикуются отдельно для каждой плоскости и в среднем по четырём
плоскостям.

### 7.4 Зафиксированный режим обучения

| Параметр | Baseline-значение |
|---|---|
| Инициализация | Kaiming для `Conv2d`, seed `42` |
| Оптимизатор | AdamW, lr $=3\cdot10^{-4}$, weight decay $=10^{-4}$ |
| Планировщик | 2 эпохи linear warmup, затем cosine decay до $10^{-5}$ |
| Батч | 16 четвёрок |
| Эпохи | 40, early stopping после 8 эпох без улучшения |
| Стабилизация | gradient clipping, норма $1.0$ |
| Точность | сеть — AMP; физический слой и loss — fp32, ядро Френеля строится в float64 и кэшируется как complex64 |
| Валидация | каждую эпоху, отдельно КК и ИСС по каждой плоскости |
| Чекпоинты | минимум `val_loss`, плюс последний |

В baseline сеть обучается с непрерывной фазой. В финальной оценке фаза обязательно сохраняется в 8-битный
PNG, считывается обратно и только после этого реконструируются четыре изображения. Quantization-aware
training, обратное распространение целей на вход сети, Fourier-признаки и адаптивные веса плоскостей пока
остаются кандидатами для последующих абляций, а не частью baseline.

## 8. Границы допустимого метода

Финальный конвейер строго имеет вид:

$$
4\ \mathrm{png}\ \longrightarrow\ f_\theta\ \longrightarrow\ \varphi
\ \longrightarrow\ \text{однократный расчёт Френеля для проверки}.
$$

После `f_θ` запрещены Gerchberg–Saxton, Фиенап, градиентная оптимизация самой фазы или иной итеративный
refinement под конкретную входную четвёрку. Это превратило бы решение в итеративную оптимизацию, а не
нейросетевой синтез. Физический слой Френеля в графе обучения и Adam для весов $\theta$ разрешены.

Классические алгоритмы можно использовать вне финального конвейера для генерации необязательных
псевдометок/данных. Любой такой эксперимент должен быть помечен в отчёте; финальный результат всегда
генерируется только одним прямым проходом сети.

## 12. Проверки корректности (тесты)

Выполнить **до** запуска обучения; они ловят основные ошибки физики.

1. **Сохранение энергии.** Для любой фазы: $\sum|K|^2\,(\lambda z)^2 = N^4$ (теорема Парсеваля при фазовом ДОЭ с единичной амплитудой).
2. **Детерминированность.** Два вызова `reconstruct(phase)` для одной фазы возвращают совпадающие результаты без NaN/Inf.
3. **Центрированная сетка.** Эталонный расчёт использует только `ifftshift → fft2 → fftshift`; замена знака БПФ или одного из сдвигов должна менять результат и считается ошибкой.
4. **Тривиальная фаза.** $\varphi\equiv0$: на выходе должна получаться изотропная картина «sinc-подобного» вида, без NaN.
5. **Круговой тест.** `phase → png → phase`: максимальная ошибка не больше $\frac{\pi}{255}$.
6. **Согласованность метрик.** КК и ИСС из `torch` и из `numpy/skimage` на одних и тех же данных отличаются не более чем на $10^{-3}$.
7. **Диапазон.** Все выходы сети лежат в $[-\pi,\pi]$, все восстановленные — в $[0,1]$, без NaN/Inf.
8. **Размер и тип png.** Все сохраняемые файлы: `mode == "L"`, `size == (128,128)`.

## Приложение А. Минимальный пример функции потерь

```python
import torch
from pytorch_msssim import ssim

def pearson_cc(a, b, eps=1e-8):
    a = a - a.mean(dim=(-2, -1), keepdim=True)
    b = b - b.mean(dim=(-2, -1), keepdim=True)
    num = (a * b).sum(dim=(-2, -1))
    den = torch.sqrt((a**2).sum(dim=(-2, -1)) * (b**2).sum(dim=(-2, -1))) + eps
    return num / den                                    # (B, C)

def doe_loss(target, recon):
    """target, recon: (B,4,N,N) в [0,1]."""
    cc = pearson_cc(target, recon)                      # (B,4)
    l = (1 - cc).mean()
    s = torch.stack([ssim(target[:, m:m+1], recon[:, m:m+1],
                          data_range=1.0, size_average=True)
                     for m in range(target.shape[1])])
    return l + 1.1 * (1 - s).mean()
```

for epoch in range(EPOCHS):
