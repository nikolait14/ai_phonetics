# Архитектурный план нейросетевого синтеза ДОЭ

## 1. Статус документа

Этот документ фиксирует гипотезы и протокол экспериментов после baseline. Он не объявляет Transformer,
Fourier-ветвь или ансамбль обязательной частью финального решения: каждая идея должна пройти отдельную
абляцию на одинаковых данных и при одинаковом режиме обучения.

Проверенные наблюдения по данным и ограничения их интерпретации вынесены в `EDA_SUMMARY.md`.

Текущая точка отсчёта по validation:

- `CC ≈ 0.366`;
- `SSIM ≈ 0.170`;
- train и validation близки, поэтому основная рабочая гипотеза — недостаточная выразительность представления
  и конфликт между четырьмя плоскостями, а не переобучение.

## 2. Неизменяемые требования задачи

- Вход: четыре независимых полутоновых изображения `uint8`, каждое размером `128×128`.
- Каждое изображение независимо нормируется на собственный максимум до диапазона `[0, 1]`.
- Порядок плоскостей фиксирован: `z = (24.1, 25.3, 26.5, 27.7)` мм.
- Выход: один фазовый ДОЭ `128×128`, общий для всех четырёх плоскостей.
- Восстановление выполняется по амплитуде `|K|`, а не по интенсивности `|K|²`.
- Физический слой использует прямой центрированный БПФ:
  `fftshift(fft2(ifftshift(...)))`.
- КК и ИСС оцениваются независимо; при прочих равных ИСС немного важнее.
- На финальном инференсе разрешён один прямой проход сети. Итеративная оптимизация конкретной предсказанной
  маски запрещена.
- Дифференцируемая физика Френеля во время обучения разрешена и обязательна для основного loss.

## 3. Общая архитектурная гипотеза

Перспективная модель должна разделять три типа обработки:

1. локальную пространственную — края, небольшие объекты, текст и мелкие детали;
2. глобальную межплоскостную — совместное согласование четырёх целей и подавление взаимных помех;
3. частотную — распределение низких и высоких пространственных частот, непосредственно связанное с
   дифракционным распространением.

Рабочая целевая схема после абляций:

```text
4 изображения
    → shared multi-scale encoder + embeddings расстояний
    → spatial / cross-plane / Fourier experts
    → обучаемое объединение признаков
    → один decoder
    → один phase-only комплексный выход
    → 4 фиксированных слоя Френеля
    → CC и SSIM по каждой плоскости
```

Это не четыре независимые сети для четырёх изображений. Все плоскости должны участвовать в одном общем
решении, поскольку полезный сигнал одной глубины способен создавать шум на остальных.

## 4. Правила построения ансамбля

- Не усреднять предсказанные фазы арифметически: углы `-π` и `+π` физически близки, но их среднее равно нулю.
- Предпочитать объединение внутренних признаков с одним общим фазовым decoder.
- Если потребуется объединять готовые фазовые гипотезы, делать это на единичной комплексной окружности:

  ```text
  H_k = exp(i φ_k)
  H = sum(w_k H_k) / (|sum(w_k H_k)| + eps)
  φ = arg(H)
  ```

- Отдельные эксперты могут специализироваться по пространственному масштабу, частотам или типу изображения,
  но каждый финальный эксперт должен учитывать все четыре плоскости.
- Полноценный mixture-of-experts добавляется только после подтверждения кластеров сложности в EDA.

## 5. Последовательность экспериментов

Каждый следующий эксперимент меняет только один существенный компонент. Dataset, split, seed, физический
слой, loss, optimizer и расписание learning rate сохраняются, если явно не указано обратное.

### A. Unit-complex output

Заменить скалярный выход `φ = π tanh(y)` на два канала:

```text
H = (a + i b) / sqrt(a² + b² + eps)
φ = atan2(b, a)
```

Гипотеза: непрерывное представление на окружности устраняет искусственный разрыв между `-π` и `+π` и
насыщение `tanh`.

### B. Shared encoder + distance embeddings — текущий эксперимент

Цель: проверить, помогает ли одинаковое извлечение признаков из всех изображений вместе с явным указанием
физической глубины.

```text
I_m → один общий encoder E → F_m
z_m → depth MLP → e_m
F_m + e_m → concat по плоскостям → 1×1 fusion
multi-scale fused features → обычный U-Net decoder → φ
```

Ограничения эксперимента B:

- encoder имеет общие веса для всех четырёх изображений;
- каждое `z_m` нормируется и кодируется небольшим MLP отдельно на каждом масштабе;
- признаки четырёх плоскостей объединяются конкатенацией и `1×1`-свёрткой;
- используются multi-scale skip connections;
- Transformer, self-attention, Fourier-блоки и mixture-of-experts отсутствуют;
- фазовая голова остаётся baseline-вариантом `π tanh`, чтобы не смешивать B с экспериментом A;
- физический слой и loss совпадают с baseline.

Контракт модели:

```text
input:  (B, 4, 128, 128), float, [-1, 1]
output: (B, 1, 128, 128), phase in [-π, π]
```

### C. Cross-plane Transformer

Добавить attention только в bottleneck после shared encoder. Полноразмерный pixel-wise Transformer не
использовать: точные детали должны проходить через convolutional skip connections.

### D. Spatial/Fourier dual branch

Добавить параллельные spatial и Fourier-ветви и обучаемое объединение их признаков. Гипотеза принимается,
если выигрыш наиболее заметен на высокочастотных примерах из EDA.

### E. Mixture-of-experts

Добавлять только если EDA показывает устойчивые группы с различным поведением: например, разреженные
процедурные объекты и натуральные текстуры. Эксперты объединяются на уровне признаков, после чего один общий
decoder строит фазу.

### F. HarmonicMoE — активная сложная архитектура

Поверх shared plane-wise encoder добавляются три bottleneck-эксперта:

- spatial residual expert для локальных контуров и малых объектов;
- cross-plane Transformer expert для глобального конфликта четырёх глубин;
- Fourier expert с обучаемым комплексным спектральным фильтром;
- sample-wise gate по статистикам входа и pooled expert features;
- balance loss, препятствующий раннему схлопыванию gate в одного эксперта.

Эксперты объединяются на уровне признаков, поэтому результатом остаётся одна фазовая маска. Полная система,
включая слой Френеля и loss, оборачивается в `DataParallel`, чтобы FFT также считался на обеих GPU.

### G. Learned phase harmonizer и DDP — финальный сложный pipeline

После первичной маски HarmonicMoE выполняется один фиксированный физически информированный correction-stage:

```text
phi0 = HarmonicMoE(X)
R0 = Fresnel(phi0)
delta = Harmonizer([X, R0, X - R0, phi0/pi])
phi_final = arg(exp(i phi0) * delta_unit_complex)
R_final = Fresnel(phi_final)
```

Harmonizer инициализируется единичной комплексной поправкой и не меняет первичную фазу в начале обучения.
Loss содержит основную метрику финального восстановления, вспомогательную метрику первичной маски и малый
штраф на величину поправки. Это два фиксированных learned-stage без итеративной оптимизации на инференсе.

Обучение переведено на `DistributedDataParallel`: `torchrun` создаёт отдельный процесс на каждую GPU,
каждый процесс считает backbone, оба прохода Френеля, harmonizer и локальный loss.

#### Полная карта тензоров

| Этап | Операция | Выход |
|---|---|---|
| Вход | 4 max-normalized изображения | `(B,4,128,128)` |
| Plane reshape | каждое изображение обрабатывается отдельно общими весами | `(4B,1,128,128)` |
| Encoder L0 | `DoubleConv 1→32`, depth embedding, plane fusion для skip | planes `(B,4,32,128,128)`, skip `(B,32,128,128)` |
| Encoder L1 | `DoubleConv 32→64` | planes `(B,4,64,64,64)`, skip `(B,64,64,64)` |
| Encoder L2 | `DoubleConv 64→128` | planes `(B,4,128,32,32)`, skip `(B,128,32,32)` |
| Encoder L3 | `DoubleConv 128→256` | planes `(B,4,256,16,16)`, skip `(B,256,16,16)` |
| Bottleneck | `DoubleConv 256→512` | `(B,4,512,8,8)` |
| Spatial expert | residual `512→256→512`, depthwise `3×3` | `(B,512,8,8)` |
| Transformer expert | `256` tokens, `512→256`, 2 layers, 8 heads, FFN `768`, plane fusion | `(B,512,8,8)` |
| Fourier expert | `512→128`, `rfft2 8×5`, complex weights, `irfft2`, `128→512`, plane fusion | `(B,512,8,8)` |
| Gate | 16 image stats + 1536 pooled expert features, MLP `1552→256→3`, softmax | `(B,3)` |
| Expert fusion | взвешенная сумма трёх expert maps | `(B,512,8,8)` |
| Decoder | `512→256→128→64→32` со skip connections | `(B,32,128,128)` |
| Initial head | `Conv1×1`, `π·tanh` | `phi0: (B,1,128,128)` |
| Fresnel pass 1 | четыре расстояния | `R0: (B,4,128,128)` |
| Harmonizer input | `[target(4), R0(4), target-R0(4), phi0/π(1)]` | `(B,13,128,128)` |
| Harmonizer encoder | `13→32→64→128`, bottleneck `128` | `(B,128,16,16)` |
| Harmonizer decoder | `128→128→64→32`, skip connections | `(B,32,128,128)` |
| Circular correction | 2 канала, unit-complex normalization | `(B,2,128,128)` |
| Final phase | `arg(exp(i·phi0)·correction)` | `(B,1,128,128)` |
| Fresnel pass 2 | четыре расстояния | `(B,4,128,128)` |

Полный loss:

```text
L = L_metric(final)
  + 0.2 * L_metric(initial)
  + 0.01 * mean(1 - cos(delta_phi))
  + 0.01 * L_gate_balance

L_metric = mean[(1 - CC) + 1.5 * (1 - SSIM)]
```

Исходный код архитектуры находится в `src/models/harmonic_moe_harmonizer.py`. Kaggle notebook содержит ту
же модель внутри генерируемого DDP script, поэтому остаётся self-contained.

## 6. Требования к EDA

EDA должен связать свойства данных с качеством baseline, а не ограничиваться общими гистограммами.

Обязательные результаты:

- проверка размеров, диапазонов, нормировки, почти пустых изображений и дубликатов между split;
- распределения среднего, дисперсии, энтропии, разреженности, плотности границ и доли высоких частот;
- сравнение procedural и BSDS, а также четырёх позиций внутри четверки;
- попарные КК, ИСС и спектральное сходство изображений внутри четверки;
- CC и SSIM baseline отдельно по каждой плоскости и для каждой группы сложности;
- лучшие, худшие и конфликтные примеры (`CC` высокий при низком `SSIM` и наоборот);
- гистограмма фазы, доля значений около `±π`, круговая статистика и спектр маски.

EDA определяет следующий шаг:

| Наблюдение | Архитектурная гипотеза |
|---|---|
| Ошибка растёт с конфликтностью четверки | cross-plane Transformer |
| Высокие частоты заметно сложнее | Fourier-ветвь |
| Глобальная форма восстанавливается плохо | Transformer/global branch |
| Одна глубина систематически хуже | depth conditioning / plane adapters |
| Procedural и BSDS образуют разные режимы | mixture-of-experts или балансировка данных |
| Фаза насыщается около `±π` | unit-complex output |
| Все группы одинаково слабы | общая ёмкость, обучение или loss, а не ансамбль |

## 7. Протокол сравнения

Для каждого запуска сохраняются:

- конфигурация и seed;
- число параметров модели;
- `train_loss` и `val_loss` по эпохам;
- `CC` и `SSIM` отдельно для каждой из четырёх плоскостей;
- средние `CC_mean`, `SSIM_mean`;
- худшие по плоскостям `CC_min`, `SSIM_min`;
- лучший checkpoint по validation loss;
- по возможности отдельные checkpoints с лучшим `CC_mean` и лучшим `SSIM_mean`;
- примеры исходных изображений, восстановлений, ошибок и фазовых масок.

Основные критерии принятия эксперимента:

1. улучшение validation SSIM без заметного ухудшения CC;
2. отсутствие систематического провала одной плоскости;
3. выигрыш воспроизводится не только на procedural или только на BSDS;
4. модель сравнивается с baseline при одинаковом протоколе;
5. усложнение архитектуры оправдывается устойчивым, а не единичным улучшением.

## 8. Текущий следующий шаг

Эксперимент B завершён: shared encoder + distance embeddings устойчиво улучшает КК и худшую плоскость, но
на dataset v2 ухудшает ИСС синтетических изображений. Первый sweep веса SSIM был недействителен: из-за
ошибки реализации все ветки фактически использовали множитель `1.1`.

Исправленный sweep завершён: shared-depth с весом SSIM `1.5` прошёл критерии на seed 42, а на seed 43
улучшил обе средние и обе худшие метрики, хотя прирост КК оказался ниже консервативного порога. Средний эффект
двух seed положителен.

Shared-depth v1 остаётся контрольной архитектурой. Финальный сложный кандидат — HarmonicMoE с learned phase
harmonizer. Loss сохраняет вес SSIM `1.5`; luminance loss не используется. Обучение выполняется на полном
dataset v2 через двух-GPU DDP и float16 render cache. Точные числа находятся в `EXPERIMENT_LOG.md`.
